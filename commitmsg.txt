fix(mac): conversions wrote /g/tmp, app read /tmp -- every path yielded 0 hashes

audit-sweep found it and the guest confirmed it. Five conversion sites ran
"hcxpcapngtool --all -o /g/tmp/X.22000" while the very next line cat-ed
/tmp/X.22000. Nothing in the tree ever created /g -- no mkdir, no symlink in
any .sh, .py or .md; the VM build scripts only set up /newroot. Proven live:
  ls: /g: No such file or directory
  sh: can't create /g/tmp/probe_g.22000: nonexistent directory
The converter's error went to a swallowed stderr, so the app asked for a file
that had never been written and got nothing, silently, on every path: cold,
sweep and scan alike. hashstore agrees -- newest .22000 is Oct 25, zero files
newer than Nov 01, while the app has been capturing all month.

git log -S traces it to 962255df, which changed the -o path and left the
paired cat alone; 9596a4bc then copied the broken pattern into the cold block.
This is why the card being off the bus was not the only thing standing between
us and a hash: even a perfect capture would have produced none.

Also from the same review:
- cap backup marker now carries the pre-walk cutoff, not the completion clock.
  Files the capture thread touches during the up-to-900s push window were
  permanently skipped by the next "mtime > since" test. Re-sending a few
  duplicates is cheap; losing the only copy off this Mac is not.
- tar returncode and archive size now checked. tar exits 1 on "file changed
  as we read it" and still leaves a plausible archive, which was being pushed
  and then marked as delivered. Failed archives are removed instead of kept.
- _rotate_capstore no longer deletes a capture newer than the backup marker.
  Rotation under the 8GB cap could drop an unpushed pcap before the 300s loop
  ever ran; it now holds it and reports unpushed_hold=N.
- A walk that finds no files at all now says walk_empty dirs_unreadable, so a
  permissions problem stops looking like a quiet afternoon.
- n_ch on the cold path is 4, not 0, and done_ch counts the four phase
  markers. Zero switched off the "partial N/M ch flushed" reading exactly on
  the one path that measures how long the card lived.
- Cold round re-timed to 84s of work (18+15+16+15+10+10, budget 95) so both
  harvests and both verdicts fit inside the measured 45s card life as far as
  the card-dependent part can; the first flush still lands at 18s.
- Removed the txpower block guarded by "and False" whose comment claimed it
  still ran, so nobody hunts for a TXPOWFAIL that cannot be emitted.
