add capture backup loop: raw pcapng finally leaves the Mac

Nothing in this app ever moved a capture off the machine. _sync_loop and
_backfill_upload both carry hashes only, so 54 MB of pcapng lived solely on
a borrowed M2 with a return date. Raw capture is the asset: a hash can be
re-extracted from a pcap, never the other way round.

One tarball per batch rather than one scp per file, because a tarball lands
whole or not at all, so the timestamp marker can only advance across data
that is provably complete. capstore and hashstore travel together, which is
what keeps an old capture re-crackable later. Offline is the normal state at
the field site, so a failed push logs one deferred line and stays quiet.

Verified live: first run pushed 842 files / 2417984 bytes in 1.1s and the
tarball landed in D:/wifi_captures/m2/incremental; second run pushed
nothing (0.0s, no event); after adding one file the run reported
pushed=1 bytes=150 and the matching tarball arrived. Daemon pid 83254
started after the file mtime, so the loop is live, not merely on disk.

Also verified separately: the existing 54 MB archive is now on Windows and
on the NAS under the same sha256 b157496a1f6815de27e73f64bc4da75c7221741d
6da1883a93173e3f5005fc08, extraction tested (848 files, 58086280 bytes,
170 pcapng, 670 .22000, 1 .pot).
