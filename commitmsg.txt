fix(mac): stop ripping the card out of the driver mid-probe; diagnose link speed

The card has been on the Mac bus all evening. Every "card off bus" reading I
took today was a false negative from my own probe: this machine prints
idVendor in decimal (5263), and the pattern I simplified this afternoon
searched only for the hex form "(0x148f" after dropping the decimal branch
that used to save it. The app itself was fine -- _card_health uses the
decimal form and correctly reported the card as present.

Two real defects behind that noise:

1. hotadd_adapter waited a fixed 4 seconds, asked wlan_ok(), got False, and
   reported a failed hot-add. The guest needs about 16 seconds to load
   rt2870.bin before wlan0 exists -- the serial log shows phy0 coming up at
   t=15.6s. So the next cycle issued device_del straight through a probe
   that was still running, producing "Vendor Request 0x07 failed ... error
   -19" and "Invalid RT chipset 0x0000, rev 0000 detected". We were
   generating the very errors we were reading as evidence of a dead card.
   Now: ask the monitor whether the device is already attached and, if it
   is, wait instead of yanking; poll for wlan0 up to 45s rather than
   guessing once at 4s.

2. _card_health classified the card via "system_profiler SPUSBDataType |
   grep -ci 802.11 n". system_profiler returns 0 bytes in 0 seconds with
   rc=0 on this machine, so the grep always said 0 and every present card
   was called a zombie and put into a 60s backoff. Switched to ioreg.

What is actually wrong right now is not in this commit. The Mac negotiates
the dongle at Full Speed and QEMU passes it through at 1.5 Mb/s, so the
guest enumerates nothing at all -- its log shows only the two virtual xhci
hubs (idVendor 1d6b) and no 148f. Releasing the device from QEMU and
re-adding it does not change the number, so no software on this path can
renegotiate it. At 23:11 the same card enumerated high-speed and wlan0 came
up, which is why this reads as a contact fault rather than a dead chip.

Added _link_speed so the app logs the number instead of me having to ask.
It logs raw rather than thresholding because the high-speed value has not
been observed on this machine yet.

Self-inflicted during this change: inserted two 8-space lines directly after
a 12-space if-block, which is an IndentationError, and the daemon runs that
file so the app was down until the next deploy. Second indentation slip today
from the same habit -- splice by line and re-read the block, always.
